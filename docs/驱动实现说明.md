# 显示与触屏：实现说明

所有参数都来自原厂 `dtbo_a` 里的设备树节点，不是试出来的。原始节点见 `reference/sofef03f-panel-node.dts`。

## 一、显示

### 1. 硬件连接

| 信号 | 来源 | 主线节点 |
|---|---|---|
| DSI0 模拟电 1.2V | PM8150L LDO3 | `vdda-supply = <&vreg_l3c_1p2>` |
| DSI PHY 0.875V | PM8150L LDO5 | `vdds-supply = <&vreg_l5a_0p875>` |
| 面板 I/O 1.8V | PM8150L LDO14 | `vddio-supply = <&vreg_l14a_1p8>` |
| 复位 | TLMM GPIO 6，低有效 | `reset-gpios` |
| TE（撕裂同步） | TLMM GPIO 8 | `te-gpios` + pinctrl `mdp_vsync` |
| 面板偏压 lab/ibb | PM8150L LCDB | **主线无驱动** |

TE 那根线在 pinctrl 里复用成 `mdp_vsync`，直接进 DPU，不需要驱动去收中断 —— 这是命令模式面板能正常出图的关键，漏了就只有第一帧。

### 2. 面板模式

- 1080×2400，60Hz，**命令模式**（`dsi->mode_flags` 里不能有 `MIPI_DSI_MODE_VIDEO`）
- 4 lane，RGB888
- 必须开 DSC，否则带宽不够

时序（来自原厂 `timing@0`）：

```
hfp 52   hpw 24   hbp 24
vbp 8    vfp 1208 vpw 4
clock = 1180 × 3620 × 60 / 1000 = 256296 kHz
```

vfp 特别大是因为命令模式：一帧 2400 行有效 + 1220 行消隐。

### 3. DSC 参数

从原厂 `SET_PPS`（0x9E）包逐字段解出来的，驱动里原样写进 `struct drm_dsc_config`：

| 参数 | 值 |
|---|---|
| DSC 版本 | 1.1 |
| 图像 | 1080 × 2400 |
| slice | 540 × 30（2 片） |
| slice_chunk_size | 540 |
| bits_per_component | 8 |
| bits_per_pixel | 0x80（8.0，4 位小数） |
| line_buf_depth | 9 |
| block_pred_enable | 1 |
| convert_rgb | 1 |
| rc_model_size | 8192 |
| initial_xmit_delay | 512 |
| initial_dec_delay | 526 |
| initial_scale_value | 32 |
| scale_increment_interval | 739 |
| scale_decrement_interval | 7 |
| first_line_bpg_offset | 12 |
| nfl_bpg_offset | 848 |
| slice_bpg_offset | 868 |
| initial_offset | 6144 |
| final_offset | 4336 |
| flatness min/max QP | 15 / 60 |
| rc_edge_factor | 6 |
| rc_quant_incr_limit0/1 | 11 / 11 |
| rc_tgt_offset high/low | 3 / 3 |
| rc_buf_thresh | 14 28 42 56 70 84 98 105 112 119 121 123 125 126 |
| rc_range_params | 15 组（min_qp / max_qp / bpg_offset） |

驱动里 `rc_range_params[]` 是一张 `sofef03f_ranges[15][3]` 表，值直接从 PPS 第 58..87 字节解出来。

**注意**：DSC 的 PPS 有两份。一份是面板初始化时用 DSI 发过去的（`0x9E`，驱动里 `sofef03f_pps[]` 原样保留），另一份是 DPU 的 DSC 硬件寄存器（由 `drm_dsc_config` 生成）。两份必须一致，所以驱动里既保留了原始 PPS 数组，又把同样的值填进 `drm_dsc_config`。

### 4. 初始化序列

43 个 DSI 包，554 字节，逐包翻译成 `mipi_dsi_dcs_write_seq_multi()`：

```
0x9d 0x01            ← 厂商命令，开 DSC 相关
0x9e <128 字节 PPS>  ← 原样发送
0x11                 ← sleep out，等 10ms
0xf0 0x5a 0x5a ...   ← 一堆厂商寄存器（0xb0 分页、0xb7、0xdf、0xd5、0xec、0xe4、0xe9、0xfc、0x53、0x60）
0x2a / 0x2b          ← 有效区 0..1079 / 0..2399
0x51 / 0x53          ← 亮度 / 控制
0x29                 ← display on（前面等 60ms）
```

关屏序列 2 个包：`0x28 0x00`（display off，等 20ms）、`0x10 0x00`（sleep in，等 100ms）。

复位序列来自 `qcom,mdss-dsi-reset-sequence = <1 10 0 1 1 10>`：物理高 10ms → 低 1ms → 高 10ms。主线 `reset-gpios` 是低有效，所以逻辑值反过来写。

想重新生成驱动（比如换面板或改参数）：

```bash
# 先把原厂节点导成 /tmp/sofef03f_node.dts
python3 tools/gen_panel_driver.py
```

### 5. 为什么去掉 simple-framebuffer

原 DTS 里有个 `framebuffer@9c000000`，指向启动器留下的 splash 缓冲。它和真正的 DRM 驱动抢同一块显存，而且靠"启动器画好 + 内核裸写内存"这种方式天生不稳（同一套组合一次正常一次花屏，之前已经踩过）。所以补丁把它删了，`fb_mem` 的 reserved-memory 保留，避免内核把别的东西分配到那块区域上。

## 二、触屏

### 1. 硬件连接（原厂 fragment@99 → `qupv3_se17_i2c`）

| 项 | 值 |
|---|---|
| 总线 | QUPv3 SE17 = `i2c@c80000` = 主线 `i2c17` |
| 地址 | 0x20 |
| 中断 | TLMM GPIO 122，电平低有效 |
| 复位 | TLMM GPIO 54，低有效 |
| 模拟电 | PM8150L LDO17，3.008V |
| I/O 1.8V | GPIO 119 控制的负载开关 → fixed regulator `tp_1v8` |
| 触控区 | 1079 × 2339 |
| TX/RX | 16 × 33 |

原厂 compatible 是 `synaptics-s3706`（厂商自定义驱动），主线不认。这颗芯片本身走 RMI4 协议，所以用主线的 `syna,rmi4-i2c`，功能上等价。

### 2. rmi4 补丁在干什么

主线 `drivers/input/rmi4/rmi_i2c.c` 会读 `syna,reset-delay-ms`，但**从来不去拉复位脚** —— binding 里写了 `reset-gpios`，代码里没有实现。结果就是被启动器按在复位状态的芯片永远不应答。

补丁加了：probe 时取可选 `reset-gpios`，拉低 20ms 再拉高，然后等 `syna,reset-delay-ms`。没有这个属性的板子行为不变。

### 3. 为什么是 i2c17 不是 i2c5

`i2c5` 是 `0x894000`（QUPv3 WRAP0 SE5），触屏不在那儿。原厂 dtbo 的 fixup 写得很清楚：

```
qupv3_se17_i2c = "/fragment@99:target:0"
```

`qupv3_se17_i2c` 在 stock DTB 的 aliases 里是 `/soc/i2c@0xc80000`，对应主线 `i2c17`。

## 三、上机排查

### 显示

```bash
dmesg | grep -iE 'drm|dsi|dpu|panel|sofef'
ls /dev/dri
cat /sys/class/drm/card0-DSI-1/status
```

| 现象 | 大概率原因 |
|---|---|
| 没有 `/dev/dri/card0` | `mdss` / `mdss_dsi0` 没 probe，看 dmesg 里 regulator 或 clock 报错 |
| 有 card0 但屏幕全黑、背光不亮 | **LCDB lab/ibb 没电**（主线没驱动，靠启动器留） |
| 有 card0、屏幕亮但花屏/错位 | DSC 参数或 slice 配置不对，对照上面表格 |
| DSI timeout / ack error | PHY 电压、lane 数、时钟频率 |
| 只出第一帧然后不动 | TE 没接上，检查 pinctrl `mdp_vsync` |

### 触屏

```bash
dmesg | grep -i rmi
i2cdetect -y 17            # 看 0x20 有没有 ACK
cat /proc/interrupts | grep -i -E 'rmi|122'
ls /dev/input/
evtest /dev/input/eventX
```

| 现象 | 排查 |
|---|---|
| `i2cdetect` 0x20 不 ACK | 先查 `tp_1v8`（GPIO119）和 LDO17 有没有起来；再查复位时序 |
| ACK 但 probe 失败 | 看 rmi4 报的 bootloader/ firmware 状态，可能要 `syna,startup-delay-ms` 调大 |
| 有 input 设备但没事件 | 中断没触发：GPIO122 的 pinctrl、`interrupt-parent`、电平极性 |
| 坐标反了/范围不对 | `syna,clip-x-high` / `clip-y-high`，或者加 `touchscreen-swapped-x-y` |

## 四、下一步

1. **PM8150L LCDB 驱动**（`qpnp-lcdb`）。主线那个 `qcom-labibb-regulator.c` 是 PMI8998 系 SPMI 的，寄存器不一样，不能直接用。有了它才能不依赖启动器偏压。
2. 亮度曲线。现在 `set_display_brightness` 是线性映射到 0..2047，原厂有 gamma 表，观感会差一些。
3. 上游化：binding 的 `maintainers` 和补丁的 `Signed-off-by` 换成真实信息，跑 `checkpatch.pl --strict`。
