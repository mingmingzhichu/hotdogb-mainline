# PM8150L LCDB：lab/ibb 偏压驱动（2026-11-27）

## 结论

主线原来没有 PM8150L 的 LCDB 驱动。现成的 `qcom-labibb-regulator.c` 是给 PMI8998 那代的：
LAB 和 IBB 是两个独立的 SPMI 外设（基址 `0xde00` / `0xdc00`），各自一套寄存器。PM8150L 把两路
合成了一个 **LCDB** 外设（基址 `0xec00`）：LDO 出正压、NCP（反相电荷泵）出负压、上面共用一个
boost，`0x46` 一个 `MODULE_EN` 位管两路。

所以补丁 0015–0018 新写了一个 `drivers/regulator/qcom-lcdb-regulator.c`：

- 两路输出 `lab`（ELVDD，正）和 `ibb`（ELVSS，负），`n_voltages = 32`
- 共享的 module enable：谁先开谁把模块带起来，最后一个关掉时才真正下电
- 上电按 `VREG_OK`（`0x10` bit0）握手，超时就回滚 `MODULE_EN` 并报错
- 下电走 `LDO_FORCE_PD`（`0x79`）快速放电，等 10ms 再撤

面板驱动（0017）把 `lab`/`ibb` 加进 supply 表，`prepare()` 里跟 `vddio` 一起开，顺序是
vddio → lab → ibb，跟原厂 supply table 一致。板级 DTS（0018）把 PM8150L 节点加了 label，
挂上 `lcdb@ec00`，两路都定 4.6V。

**编译、DTB、checkpatch 都过了；真机还没验证。**

## 硬件位置

| 项目 | 值 |
|---|---|
| LCDB 外设 | PM8150L SPMI USID 4，地址 `0xec00` |
| ELVDD（正） | LDO 输出，`0x71`，4.0–6.0V；<4.95V 用 100mV 步进，之上 50mV |
| ELVSS（负） | NCP 输出，`0x81`，编码同上 |
| 共享 boost | `0x41`，4.7–6.275V，25mV 步进 |
| boost 关系 | `Vout = max(lab, abs(ibb)) + headroom`，headroom 默认 150mV |
| 模块使能 | `0x46` bit7 `MODULE_EN`，`0x45` bit7 `MODULE_RDY` |
| 实时状态 | `0x10` bit0 `VREG_OK`，bit1 `SC_ERROR` |

电压编码这段（两段式）反直觉，所以两边都留了注释：

```
uv < 4.95V : sel = ceil((uv - 4.0V) / 100mV)
uv >= 4.95V: sel = ceil((uv - 4.95V) / 50mV) + 10
```

## 为什么是 4.6V

原厂 `dsi_panel_pwr_supply` 给 `lab`/`ibb` 的都是 `4.6V ~ 6.0V` 的范围，而
`qpnp_lcdb_ldo_regulator_set_voltage()` 用的是 `min_uV`，所以真机上这两路就是 4.6V。
`dtbo_a` 里 `ldo`/`ncp` 子节点写的也是 4.0–6.0V 的范围（不是定值），跟这个对得上。

**这条最值得怀疑。** 如果真机上出现整屏偏色、亮度上不去、或者亮一会儿掉电，先把 4.6V 往上调。

## 跟启动器的关系

ABL 为了连续启动画面（continuous splash）会把 LCDB 打开并配好，所以"没有驱动也能亮"一直是
因为这个状态没被清掉。驱动的 probe 里：

- `MODULE_EN = 1` → 不重写任何寄存器，只把当前电压读回来记在软件账本里（否则第一次
  `set_voltage` 会把 boost 头寸算错）
- `MODULE_EN = 0` → 补 `MODULE_RDY`，按 DT 把两路电压和 boost 写好，等第一次 enable

另外 `regulator_enable()` 有一个坑：内核发现硬件已经开着的会直接跳过驱动的 `.enable`，
这时软件里的使能计数是 0。所以 `.disable` 里不能因为计数是 0 就返回 `-EINVAL`，否则关屏
时偏压永远关不掉。

## 已验证

- 干净 `linux-7.3.3` 上把 0000–0018 按 CI 的方式（`patch -p1 --batch --forward`）全部打进去，无冲突
- `qcom-lcdb-regulator.o`、`panel-samsung-sofef03f.o`、`sm8150-oneplus-hotdogb.dtb` 都编过
- DTB 里 `lcdb@ec00` 带两个子节点，面板节点 `lab-supply`/`ibb-supply` 指向它们
- `checkpatch.pl --strict`：0 error 0 warning

## 未验证 / 风险

- **真机上下电**：`regulator_summary` 里两路电压对不对、unprepare 之后是不是真掉到 0
- **4.6V 是否够**（见上）
- 短路中断没接，`SC_ERROR` 只会打一条 warning，不会自动恢复
- 触摸唤醒（TTW）、ILIM、PFM、soft-start 全部保持 ABL 留下的值
- 掉电后重新上电这条路径（原来 ABL 一直在保底，现在驱动会真的把它关掉一次）
