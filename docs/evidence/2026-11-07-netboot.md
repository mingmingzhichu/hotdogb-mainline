# Netboot：NBD rootfs（2026-11-07）

## 方案来源

postmarketOS 的 netboot 不是 NFS，而是 **NBD over USB 网卡**：

```
设备 initramfs                    主机 (PC)
─────────────────                ─────────────────
RNDIS gadget, 172.16.42.1  <--->  172.16.42.2/24
nbd-client 172.16.42.2 9999  --->  nbd-server 导出 rootfs.img
mount /dev/nbd0 /newroot
switch_root
```

好处是 NBD 只有一条 TCP 连接，Windows 上可以用一个 Python 脚本直接当服务端，
不需要 NFS 的 portmapper/mountd，也不用写设备分区。

## 本仓库的实现

- `configs/hotdogb-netboot.config`：`CONFIG_BLK_DEV_NBD=y`
  （必须内建，initramfs 挂 root 时还没有模块可加载）
- `initramfs/init`：`hotdogb.netboot=1` 时
  1. 在已有 gadget 上增加 `rndis.usb0`（同时保留 ACM 控制台）
  2. `ip addr add 172.16.42.1/24 dev usb0`
  3. `nbd-client -b 4096 -t 30 172.16.42.2 9999 /dev/nbd0`，失败重试 15 次
  4. 挂 `/dev/nbd0`（有分区则用 `nbd0p1`），`switch_root`
  5. 任何一步失败就留在 initramfs，串口可用
- `tools/nbd_server.py`：固定 newstyle + `NBD_OPT_EXPORT_NAME`，正是 BusyBox
  `nbd-client` 说的话；支持读写/flush/trim，Windows/Linux 都能跑
- `tools/make_netboot_rootfs.sh`：`mke2fs -d` 直接把 rootfs 目录写成 ext4，
  不需要 root，也不需要分区表

## 已验证

- Debian `busybox-static:arm64` 1.38.0 自带 `nbd-client / udhcpc / switch_root`
  （已解包确认），CI 不再自己编译 busybox 也不影响 netboot。
- BusyBox `nbd-client` 源码行为：读 16 字节握手 → 读 2 字节 handshake flags →
  写 4 字节 client flags=0 → `NBD_OPT_EXPORT_NAME` → 读 8+2+124 字节。
  `tools/nbd_server.py` 按这个实现。
- Python 协议自测通过：握手、size=1 MiB、flags=5、124 字节填充、
  READ/WRITE 回环、末尾块读取都正确。
- rootfs 镜像构建通过：Alpine minirootfs 3.20.3（3.9 MB）→ 2 GiB ext4，
  `e2fsck -fn` 干净；initramfs（Debian busybox）压缩后 1.03 MB，
  在 fastboot 的 ~2.7 MB 预算内。
