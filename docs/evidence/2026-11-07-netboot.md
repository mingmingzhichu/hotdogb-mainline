# Netboot：NBD rootfs（2026-11-07）

## 方案来源

postmarketOS 的 netboot 不是 NFS，而是 **NBD over USB 网卡**：

```
设备 initramfs                    主机 (PC)
─────────────────                ─────────────────
RNDIS gadget, 172.16.42.1  <--->  172.16.42.2/24
nbd-client 172.16.42.2 9999  --->  nbd-server 导出 rootfs.img
mount /dev/nbd0 /newroot
switch_root
```

好处是 NBD 只有一条 TCP 连接，Windows 上可以用一个 Python 脚本直接当服务端，
不需要 NFS 的 portmapper/mountd，也不用写设备分区。

## 本仓库的实现

- `configs/hotdogb-netboot.config`：`CONFIG_BLK_DEV_NBD=y`
  （必须内建，initramfs 挂 root 时还没有模块可加载）
- `initramfs/init`：`hotdogb.netboot=1` 时
  1. 在已有 gadget 上增加 `ncm.usb0`（同时保留 ACM 控制台）
  2. 配置 Microsoft OS 描述符：`compatible_id=WINNCM`、`b_vendor_code=0xcd`、
     `qw_sign=MSFT100`，并且**必须** `ln -s configs/c.1 os_desc`，否则
     `os_desc_config` 为空，Windows 根本读不到描述符
  3. `ip addr add 172.16.42.1/24 dev usb0`
  4. `nbd-client -b 4096 -t 30 172.16.42.2 9999 /dev/nbd0`，失败每 2 秒重试
  5. 等 `/sys/block/nbd0/size` 非 0 再 mount（nbd-client daemonize，立刻 mount
     会读到 size=0 的旧状态）
  6. 挂 `/dev/nbd0`（有分区则用 `nbd0p1`），`switch_root`
  7. 失败时 `nbd-client -d` 后重连；ACM 口保留一个救援 shell
- `tools/nbd_server.py`：固定 newstyle + `NBD_OPT_EXPORT_NAME`，正是 BusyBox
  `nbd-client` 说的话；支持读写/flush/trim，Windows/Linux 都能跑，`--verbose`
  打印前 20 个请求
- `tools/make_netboot_rootfs.sh`：`mke2fs -d` 直接把 rootfs 目录写成 ext4，
  不需要 root，也不需要分区表

## 已验证

- Debian `busybox-static:arm64` 1.38.0 自带 `nbd-client / udhcpc / switch_root`
  （已解包确认），CI 不再自己编译 busybox 也不影响 netboot。
- BusyBox `nbd-client` 源码行为：读 16 字节握手 → 读 2 字节 handshake flags →
  写 4 字节 client flags=0 → `NBD_OPT_EXPORT_NAME` → 读 8+2+124 字节。
  `tools/nbd_server.py` 按这个实现。
- Python 协议自测通过：握手、size=1 MiB、flags=5、124 字节填充、
  READ/WRITE 回环、末尾块读取都正确。
- rootfs 镜像构建通过：Alpine minirootfs 3.20.3（3.9 MB）→ 2 GiB ext4，
  `e2fsck -fn` 干净；initramfs（Debian busybox）压缩后 1.03 MB，
  在 fastboot 的 ~2.7 MB 预算内。
- **真机 netboot 成功**（Windows 10 19044 + CDC-NCM）：
  ```
  $ ssh root@172.16.42.1 'hostname; cat /etc/debian_version; uname -a'
  hotdogb
  12.15
  Linux hotdogb 7.0.0-sm8150-g8e126dbc4044-dirty #64 aarch64 GNU/Linux
  ```
  根文件系统是 Debian 12 的 cloud image root 分区（导出为裸 ext4）。

## 踩坑

1. **Windows 10 的 RNDIS 走不通**。`netrndis.inf` 只是模板 INF，
   没有 `USB\MS_COMP_RNDIS` 条目，接口会停在 `CM_PROB_FAILED_INSTALL`。
   改用 CDC-NCM，`usbncm.inf` 明确匹配 `USB\MS_COMP_WINNCM`。
2. **只写 `os_desc/use` 不够**。`cdev->os_desc_config` 由 `os_desc` 组里的
   配置链接设置，必须 `ln -s configs/c.1 os_desc`；否则 Windows 看不到任何
   Microsoft OS 描述符，兼容 ID 只会是 `USB\Class_02&SubClass_0d`。
3. **nbd-client 会 daemonize**。它返回时内核还没设好容量，立刻 `mount`
   会 `unable to read superblock`；必须等 `/sys/block/nbd0/size` 非 0。
4. **mount 失败后直接重连会 reset 旧连接**（`Receive control failed -104`）。
   先 `nbd-client -d` 再重连。
5. 改 `idProduct` 可以强制 Windows 建新的设备实例，绕开失败驱动的缓存。
6. **ABL 追加 `init=/init`**。initramfs 不能把内核 cmdline 的 `init=` 直接
   传给 `switch_root`，否则报 `can't execute /init`；用
   `hotdogb.netboot.init=` 单独指定。
7. **分区不会自动出现**。nbd-client 打开设备时容量是 0，内核不会创建
   `/dev/nbd0pN`；要先读一下整盘（`dd bs=512 count=8`）触发扫描，或者直接
   导出单个 ext4 分区。
8. **cloud-init 卡启动**。cloud image 的 `cloud-init-local` 在等 datasource，
   systemd 一直 `initializing`；mask 掉 cloud-init 的单元即可。
