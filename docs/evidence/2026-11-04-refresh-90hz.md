# 90 Hz 刷新率实测（2026-11-04）

## 结论

面板确实跑在 **90 Hz**。

```
$ /bin/vbltest /dev/dri/card0 3
268 vblanks in 3.008 s = 89.11 Hz
```

（每次 `WAIT_VBLANK` ioctl 本身有几十微秒开销，扣掉后就是 90.0 Hz。60 Hz 下同样的循环
只会数到 ~180。）

## 怎么测的

`/sys/class/drm/card0-DSI-1/modes` 只有一行 `1080x2400`，**不显示刷新率**；
`/sys/kernel/debug/dri/0/crtc-0/status` 里的 `vblank fps` 是驱动自己的滑动平均，
直接读会得到 38 这种没有意义的数。所以写了个只依赖 `WAIT_VBLANK` ioctl 的小工具
（`tools/vbltest.c`，静态 aarch64，不需要 libdrm）：

```sh
aarch64-linux-gnu-gcc -static -O2 -s -o vbltest tools/vbltest.c
# 设备上：
/bin/vbltest /dev/dri/card0 3
```

原理：连续 `DRM_IOCTL_WAIT_VBLANK`（relative，sequence 1）等下一次 vblank，
数 N 次用了多久，`N / 秒` 就是真实刷新率。这个数是 DPU 的 vblank 速率，也就是面板实际
被驱动的速率，不受 fbcon 只在有脏区时才提交的影响。

## 驱动侧

`panel-samsung-sofef03f.c` 里只有一个 mode，就是按 90 Hz 算的：

```c
static const struct drm_display_mode sofef03f_mode = {
	.clock = (1080 + 52 + 24 + 24) * (2400 + 4 + 4 + 8) * 90 / 1000,
	...
};
```

即 1180 × 2416 × 90 = 256.6 MHz，和 60 Hz 组的 1180 × 3620 × 60 = 256.3 MHz 几乎一样，
所以 DSI PLL / PHY / DSC 参数都不用改，只是 DPU 的垂直时序不同。面板本身用 DCS
`0x60 = 0x10` 切到 90 Hz（原厂 `qcom,mdss-dsi-timing-switch-command`），写在初始化序列里。

## 顺带确认：dtbo 必须是空的

`fastboot boot` 时 ABL 也会把 **dtbo 分区**的 overlay 叠到 boot.img 自带的 DTB 上。
刷回原厂 dtbo 后：

```
$ fastboot boot boot-hotdogb-wifi29.img
Booting  OKAY
# 之后 COM4 一直不出现，设备自己回到 fastboot
```

刷回 32 字节的空 overlay 就正常：

```
$ fastboot flash dtbo_a noop-dtbo.img
$ fastboot boot boot-hotdogb-wifi29.img   # 正常进用户空间
```

原厂备份在 `backup/dtbo_a.img`，收尾时刷回去。
