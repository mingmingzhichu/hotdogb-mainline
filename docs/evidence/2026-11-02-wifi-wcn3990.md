# WCN3990 Wi-Fi 打通记录（2026-11-02）

设备：OnePlus 7T（`hotdogb`），内核 7.0.0 主线，`fastboot boot` 启动，根文件系统是 initramfs。

## 结论

`wlan0` 能起来、能主动扫描到 AP。从冷启动到能扫，只要一条命令：

```sh
/bin/wifi_up.sh
```

要满足的前提只有一个：**`wlanmdsp.mbn` 必须来自本机的 `modem_a` 分区**，不能用别的 sm8150 机型
（7T Pro / hotdog）固件包里的那份。

## 为什么前提是它

WCN3990 不是独立芯片：它由 MPSS 带起来，ath10k 只能通过 QMI（`WLFW` 服务）跟它说话。
ath10k 在 probe 里要把 MSA 内存从 HLOS 划给 `MSS_MSA` / `WLAN` / `WLAN_CE`：

```
ath10k_snoc 18800000.wifi: qmi msa mem region 0 addr 0x8bc00000 size 0x4000 flag 0x00000001
ath10k_snoc 18800000.wifi: qmi msa mem region 1 addr 0x8bc04000 size 0x17c000 flag 0x00000000
```

用 7T Pro 的 `modem.mbn` + `wlanmdsp.mbn` 时这一步直接失败：

```
ath10k_snoc 18800000.wifi: failed to assign msa map permissions: -22
...
ath10k_snoc 18800000.wifi: failed to create WMI vdev 0: -108
```

改用本机 `modem_a`（FAT16，`image/wlanmdsp.mbn`，4 070 084 B）后，同一条 SCM 调用成功，
后面 firmware/board 下发、`wlan0` 注册全部正常。

### 不要用 `qcom,msa-fixed-perm`

在 DTS 的 `wifi@18800000` 上加 `qcom,msa-fixed-perm` 会让驱动**跳过**这次 SCM 分配。
跳过之后 WLAN 子系统访问那块内存就触发致命错误，整机直接掉进 **EDL（9002/900E）**，屏幕全黑、
COM 口消失，只能长按电源恢复。这条路不要走。

## 依赖的三个用户态服务

MPSS 起不来就会在一分钟内自己 assert，所以这三个必须先跑：

| 服务 | 作用 | 关键点 |
|---|---|---|
| `rmtfs` | 通过 QRTR 提供 modem 的 EFS | EFS 内容用 `dd` 从 `modemst1/2`、`fsg`、`fsc`、`oem_*` 拷到 `/tmp/rmtfs`，不写 flash |
| `pd-mapper` | 发布/解析保护域映射 | |
| `tqftpserv` | 提供 WLAN 固件的 `/readwrite/`（MAC、校准） | 必须能创建 `/var/lib/tqftpserv`（它的 mkdir 不是递归的），内容从 `persist` 只读拷入 |

`tqftpserv` 这一条没满足的话，MPSS 不会发布 WLFW 服务，ath10k 会一直等：

```
$ qrtr-lookup | grep ATH
       69       1       0    0    95 ATH10k WLAN firmware service
```

## 已知未完成

- `invalid MAC address; choosing random`：modem 没从 EFS 拿到 MAC。Android 是把
  `persist/wlan_mac.bin` 交给 WLAN HAL 的，主线这边还没接。
- `cfg80211: failed to load regulatory.db`：initramfs 里没有 `regulatory.db`，国家码退化成 US。
- 没有 `wpa_supplicant` / DHCP，所以只到「能扫」这一步，还不能上网。
- `modem.mbn` 目前仍用 `firmware-oneplus-hotdog`（7T Pro）里的
  `MPSS.HE.1.0.c11.1-00007`；本机 `modem_a` 是分片格式（`modem.mdt` + `modem.b00…b31`，
  `MPSS.HE.1.0.c10-00031`），要换成本机的得先让 `qcom_mdt_loader` 走分片路径。
- 冷启动有偶发失败：UFS `pwr ctrl cmd 0x18 completion timeout` + 触摸 I2C 超时 + 显示
  `enc33 reset failure`，三者同时挂，3 分钟都出不来 `sd*`。同一份 DTB 下一次启动就正常，
  与 DTB/补丁无关，是启动时序问题，还没定位。
